# 项目安全约束文档

## 文档用途

本文档定义了在使用 AI 编程工具（Claude Code）辅助开发 MorningModel 项目时的安全约束。每次开启新的 AI 对话时，应将本文档的核心约束部分完整粘贴给 AI，确保安全要求贯穿整个开发过程。

## 项目背景

MorningModel 是一个 RSS 新闻聚合系统，从 41 个外部 RSS 源抓取文章，通过 LLM（OpenAI/DeepSeek/Gemini）进行摘要和排名，最终通过邮件推送给用户。

**核心安全挑战：** 系统处理大量不可信的外部内容（RSS 文章），这些内容直接进入 LLM Prompt，存在 Prompt 注入风险。

## 安全约束条件

### 约束1：不可信内容必须经过消毒处理

- 所有来自 RSS 源的文本（标题、摘要、正文）在进入 Prompt 前，必须通过 `sanitize_untrusted_text()` 处理
- 必须移除控制字符（`\x00-\x08`, `\x0b`, `\x0c`, `\x0e-\x1f`, `\x7f`）
- 必须移除零宽字符（`​-‏`, `﻿`）
- 必须替换可能用于伪造边界的标记（如 ` ``` ` 替换为 `'''`）
- 必须支持 `max_chars` 截断，防止超长输入

### 约束2：不可信内容必须有明确边界

- 使用 `wrap_untrusted()` 函数将不可信内容包裹在 `BEGIN_UNTRUSTED_CONTENT` 和 `END_UNTRUSTED_CONTENT` 标记之间
- 每段不可信内容必须带有 `label` 标识其来源（如 `article title`, `article content`）
- 不可信内容中如果包含边界标记本身，必须将其替换为 `*_REDACTED` 变体

### 约束3：Prompt 注入检测

- 所有不可信文本在进入 LLM 前必须通过 `assess_prompt_injection()` 检测
- 检测 7 类注入模式（忽略指令、泄露 Prompt、伪造角色、篡改输出格式等）
- 检测到可疑内容时，该文章必须被排除，不得进入 LLM Prompt
- 安全研究类的良性上下文（如讨论 "prompt injection" 的文章）允许单次匹配豁免

### 约束4：系统 Prompt 安全

- 每次 LLM 调用必须通过 `secure_messages()` 构造消息，确保包含安全系统提示
- 系统 Prompt 必须明确告知模型：所有文章内容为不可信数据，仅用于判断相关性、提取事实、摘要和引用
- 禁止模型遵循不可信内容中的任何指令

### 约束5：API 密钥管理

- 所有密钥通过环境变量管理，禁止硬编码
- 日志中打印密钥时必须使用 `_get_masked_api_key()` 进行脱敏（仅显示前4后4位）
- 禁止在 Prompt 中包含 API 密钥或其他敏感配置

### 约束6：模型输出验证

- LLM 返回的文本在使用前必须通过 `validate_model_text_output()` 验证
- 如果模型输出看起来像是遵循了注入指令（包含注入模式），必须抛出异常拒绝该输出

## 禁止行为

1. **禁止** 将未经消毒的外部内容直接拼接进 Prompt
2. **禁止** 在代码中硬编码任何 API 密钥或密码
3. **禁止** 在日志中打印完整的 API 密钥或用户凭据
4. **禁止** 信任 LLM 输出而不经过验证
5. **禁止** 跳过 Prompt 注入检测直接使用外部内容
6. **禁止** 在邮件模板中插入未转义的用户输入

## AI 交互时的约束传递方式

在使用 Claude Code 开发时，通过以下方式确保安全约束被传递：

1. **CLAUDE.md 项目约束文件**：在项目根目录放置 `.claude/` 配置，包含安全开发规范
2. **Prompt 前缀**：每次请求 AI 生成代码时，明确说明 "所有外部输入必须经过 prompt_security.py 处理"
3. **代码审查提示**：要求 AI 在生成代码后自查是否遵循了上述约束
