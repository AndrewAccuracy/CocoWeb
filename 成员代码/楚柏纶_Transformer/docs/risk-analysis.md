# 风险分析记录

## 模块范围

本次修改的对象是 Causal LM 推理入口，主要涉及 `model.py` 的 `forward()` 和 `generate()`。这两个函数会接收外部传入的 token id，然后直接索引 embedding 矩阵并进入 Transformer 计算。

## 涉及的敏感操作

- 根据 `input_ids` 读取 embedding 矩阵。
- 根据输入序列长度执行注意力计算。
- 在 `generate()` 中循环调用 `forward()` 生成新 token。
- 将异常输入交给 NumPy 下标和矩阵计算处理。

## 主要安全风险

| 风险 | 可能后果 | 加固方向 |
| --- | --- | --- |
| token id 未校验 | 负数下标可能访问到非预期 embedding，超出词表范围会触发运行时异常 | 在进入模型前检查 token id 是否为整数且位于 `[0, vocab_size)` |
| 输入序列长度未限制 | 过长输入会带来额外计算开销，注意力计算对长度比较敏感 | 限制输入长度不得超过 `max_position_embeddings` |
| 生成长度未限制 | `max_new_tokens` 过大时会不断调用模型，造成资源消耗 | 根据剩余上下文长度限制生成数量 |
| 错误交给底层异常暴露 | NumPy 的异常信息不一定适合直接返回给上层调用方 | 使用统一的 `InputValidationError` 表达输入问题 |

## 安全目标

本次修改的目标是让模型入口先检查输入，再进入矩阵计算。正常输入不受影响；异常输入在靠近入口的位置被拒绝，并返回可理解的错误类型。这样既避免负数下标一类的隐蔽问题，也减少超长输入带来的资源消耗。
